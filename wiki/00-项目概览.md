# Nexus Agent Runtime Framework — 项目概览

## 1. 项目定位

Nexus 是一个**轻量级、模型无关、插件驱动的 Agent 运行时框架**，定位为"Agent 操作系统内核"。它的核心设计哲学是**关注点分离**：让 Runtime 只负责最基础、最稳定的调度能力，所有高级能力（模型、工具、策略、插件）通过抽象接口自由替换和扩展。

---

## 2. 核心设计理念

### 2.1 Runtime 与 Policy 分离

传统 Agent 框架通常将 Agent 循环硬编码为固定模式，导致：
- 难以支持不同 Agent 模式（Planning、Reflection、Multi-Agent）
- 模式与核心执行逻辑耦合
- 测试复杂（必须跑完整循环）

Nexus 的解法：
- **Runtime**：只做调度循环、状态管理、事件派发。循环是 `while True: get_action_from_policy() -> execute_action()`，不关心是哪种模式
- **ExecutionPolicy**：只做决策。通过 `next_action(context) -> Action` 接口返回 Action 对象驱动 Runtime

### 2.2 Action 调度模型

Policy 不直接调用 LLM 或 Tool，而是返回 Action 对象。Runtime 根据 Action 类型执行对应操作。

这层间接性带来三个关键好处：
1. **Policy 是纯决策函数**：可独立进行单元测试
2. **Runtime 统一处理横切关注点**：日志、事件、错误处理、超时控制
3. **未来可支持 Action 序列化/重放**：纯数据对象可发送到远程执行或写入日志

### 2.3 可扩展性策略

所有高级能力通过插件式接口扩展，Core 保持稳定不变：

| 扩展维度 | 抽象接口 | 说明 |
|---------|---------|------|
| 模型 | `BaseLLM` | 切换 OpenAI/Anthropic/本地模型只需替换实例 |
| 工具 | `BaseTool` + `ToolRegistry` | LLM 通过 Function Calling 自动发现 |
| 策略 | `ExecutionPolicy` | ReAct / Plan-Execute / Reflection 等不同模式 |
| 插件 | `Plugin` | install → activate → deactivate 完整生命周期 |
| 事件 | `EventBus` | 发布/订阅，覆盖 Agent 执行全过程 |
| 记忆 | `BaseMemory` | 短期缓存、向量检索、图记忆等不同后端 |

## 5. 快速启动

### 5.1 安装

```bash
# 基础安装
pip install -e .

# 含 CLI 依赖
pip install -e ".[cli]"

# 含 Server 依赖
pip install -e ".[server]"

# 含 MCP 依赖
pip install -e ".[mcp]"

# 开发全量
pip install -e ".[dev,cli,server,mcp]"
```

### 5.2 CLI 使用

```bash
# 一次性问答
nexus "帮我写一个快速排序"

# 交互式 REPL
nexus

# 启动服务
nexus serve --port 8321

# 带 UI 启动
nexus ui --port 8321
```

### 5.3 编程使用

```python
import asyncio
from nexus.core.agent.agent import Agent
from nexus.llm.providers.openai import OpenAILLM

async def main():
    llm = OpenAILLM(model="gpt-4o-mini", api_key="sk-xxx")
    agent = Agent(llm=llm, system_prompt="你是一个友好的助手。")
    state = await agent.run("你好，请介绍一下你自己。")
    print(state.messages[-1]["content"])

asyncio.run(main())
```

## 6. 关键术语表

| 术语 | 含义 |
|------|------|
| **Runtime** | Agent 执行中枢，负责调度循环、状态管理、事件派发 |
| **Policy** | 执行策略，决定"下一步做什么"，返回 Action |
| **Action** | Policy 返回的操作指令（LLMCall / ToolCall / Finish / Error 等）|
| **AgentState** | 运行时状态快照，包含消息历史、步骤记录、工具调用记录 |
| **Context** | 请求级 DI 容器，聚合单次运行所需的所有组件 |
| **EventBus** | 异步事件总线，发布/订阅模式，handler 异常隔离 |
| **ToolRegistry** | 工具注册中心，O(1) 查找 |
| **ToolExecutor** | 工具执行器，负责校验→执行→包装→记录 |
| **Provider** | LLM 提供商实现（OpenAI / Anthropic / MiniMax）|
| **MCP** | Model Context Protocol，外部工具协议 |
| **Session** | 会话持久化，保存对话历史到文件 |
| **Factory** | Agent 组装工厂，统一创建 LLM + Agent + 工具 |
