## 1. 事件总线 EventBus

### 1.1 定位与设计哲学

[`nexus/core/event/event_bus.py`](file:///Users/wanghanle/Documents/code/githubProject/Nexus/nexus/core/event/event_bus.py) 是框架的**事件分发中枢**。它解耦了「事件发生者」和「事件处理者」，让 Agent 的核心执行逻辑不需要关心：

- CLI 如何渲染终端输出
- Server 如何推送 WebSocket 消息
- 日志如何记录执行过程

### 1.2 核心实现

```python
class EventBus:
    def __init__(self) -> None:
        self._handlers: dict[EventType, list[EventHandler]] = defaultdict(list)
    
    async def publish(self, event: Event) -> None:
        """发布事件到所有订阅者。
        
        使用 asyncio.TaskGroup 并发执行所有 handler，
        单个 handler 异常不影响其他 handler 或主流程。
        """
        handlers = self._handlers.get(event.type)
        if not handlers:
            return
        
        async with asyncio.TaskGroup() as tg:
            for handler in handlers:
                tg.create_task(self._invoke_handler(handler, event))
    
    async def subscribe(self, event_type: EventType, handler: EventHandler) -> None:
        """订阅事件。重复订阅同一 (event_type, handler) 为幂等操作。"""
        if handler not in self._handlers[event_type]:
            self._handlers[event_type].append(handler)
    
    async def unsubscribe(self, event_type: EventType, handler: EventHandler) -> None:
        """取消订阅。未注册的 handler 静默忽略。"""
        registered = self._handlers.get(event_type)
        if registered:
            try:
                registered.remove(handler)
            except ValueError:
                pass
    
    async def _invoke_handler(self, handler, event) -> None:
        """调用单个 handler 并做异常隔离。"""
        try:
            if asyncio.iscoroutinefunction(handler):
                await handler(event)
            else:
                handler(event)
        except Exception:
            logger.warning("Handler %s raised exception", handler_name, exc_info=True)
```

### 1.3 事件类型定义

```python
class EventType(Enum):
    BEFORE_LLM_CALL = auto()   # LLM 调用前
    AFTER_LLM_CALL = auto()    # LLM 调用后（含 usage 统计）
    LLM_CHUNK = auto()         # LLM 流式 chunk 到达
    BEFORE_TOOL_CALL = auto()  # 工具调用前
    AFTER_TOOL_CALL = auto()   # 工具调用后（含 result/error）
    ON_ERROR = auto()          # 运行时错误
    ON_FINISH = auto()         # Agent.run() 完成
```

### 1.4 事件数据结构

```python
@dataclass
class Event:
    type: EventType
    payload: dict[str, Any]  # 各事件类型有不同的 payload 约定
```

各事件的 payload 约定：

| 事件类型 | payload 关键字段 | 说明 |
|----------|-----------------|------|
| `LLM_CHUNK` | `delta_content`, `delta_reasoning` | 增量文本 |
| `AFTER_LLM_CALL` | `response`, `usage` | 完整响应 + token 统计 |
| `AFTER_TOOL_CALL` | `tool_name`, `args`, `result`, `error` | 工具执行结果 |
| `ON_ERROR` | `error` | 错误信息 |
| `ON_FINISH` | `state` | 最终 AgentState |

### 1.5 使用模式：订阅 → 执行 → 取消订阅

```python
async def on_llm_chunk(event: Event) -> None:
    print(event.payload["delta_content"], end="")

await agent.events.subscribe(EventType.LLM_CHUNK, on_llm_chunk)
try:
    await agent.run("写一个快速排序")
finally:
    await agent.events.unsubscribe(EventType.LLM_CHUNK, on_llm_chunk)
```

**教学点**：为什么每次 run 都要重新订阅/取消订阅？
- 避免跨任务泄露：上一个 run 的 handler 不应影响下一个 run
- 支持动态 handler：不同场景可以订阅不同的事件处理器
- 这是「请求级生命周期」原则的体现

### 1.6 异常隔离的重要性

```python
# _invoke_handler 中的关键设计
try:
    await handler(event)
except Exception:
    logger.warning(..., exc_info=True)
    # 不重新抛出！
```

事件监控不应影响 Agent 主流程。即使日志渲染出错，Agent 的决策和执行也必须继续。

## 2. 插件系统 Plugin

### 2.1 定位与设计哲学

[`nexus/plugins/base.py`](file:///Users/wanghanle/Documents/code/githubProject/Nexus/nexus/plugins/base.py) 定义了插件的抽象接口。插件是框架**可扩展性的核心支柱**。

**与 VSCode Extension 的类比**：

| VSCode Extension | Nexus Plugin |
|------------------|--------------|
| 注册 commands | 注册 tools（`agent.tool_registry.register`） |
| 订阅 `onDidChangeTextDocument` | 订阅 EventBus 事件 |
| 注入 TreeView | 未来可对接 Web UI 面板 |
| `activationEvents` | `install()` 即为激活入口 |

### 2.2 Plugin 抽象基类

```python
class Plugin(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """插件唯一名称，用于注册中心的索引和冲突检测。"""
    
    @property
    @abstractmethod
    def version(self) -> str:
        """插件版本号，遵循 SemVer。"""
    
    @abstractmethod
    async def install(self, agent: "Agent") -> None:
        """安装插件到 Agent。
        
        在此方法中完成「声明式」注册：
        - agent.tool_registry.register(tool)
        - agent.events.subscribe(event_type, handler)
        不应启动后台任务或打开外部连接。
        """
    
    @abstractmethod
    async def activate(self) -> None:
        """激活插件 - 所有 install 完成后，正式开始工作。
        
        在此方法中启动后台任务、建立持久连接。
        """
    
    @abstractmethod
    async def deactivate(self) -> None:
        """停用插件 - 释放资源、取消订阅、停止后台任务。
        
        实现应确保幂等性——重复调用 deactivate 不会出错。
        """
```

### 2.3 插件生命周期

```
┌─────────┐    install()    ┌──────────┐    activate()    ┌──────────┐
│  初始化  │ ──────────────> │  已安装   │ ──────────────> │  运行中   │
│         │                 │          │                 │          │
└─────────┘                 └──────────┘                 └──────────┘
                                                              │
                                                              │ deactivate()
                                                              ▼
                                                         ┌──────────┐
                                                         │  已停用   │
                                                         └──────────┘
```

**三阶段分离的设计原因**：

| 阶段 | 时机 | 职责 | 为什么分离 |
|------|------|------|-----------|
| install | Agent 初始化时 | 注册工具、订阅事件 | 只做「声明」，不做「动作」 |
| activate | 所有插件 install 后 | 启动连接、后台任务 | 避免插件间竞争资源 |
| deactivate | Agent 关闭/插件卸载 | 释放资源 | 确保可干净退出 |

### 2.4 Agent 的插件注册中心

```python
class Agent:
    def __init__(self, ...):
        self.plugin_registry: PluginRegistry = PluginRegistry()
    
    async def install(self, plugin: Plugin) -> None:
        await plugin.install(self)
        self.plugin_registry.register(plugin)
        await plugin.activate()
```

## 3. EventBus + Plugin 的协作模式

### 3.1 完整事件流

```
用户输入 ──> Agent.run()
                │
                ├── publish(BEFORE_LLM_CALL)
                │       ├── CLI: 无需操作（append 模式）
                │       └── Server: 无需操作
                │
                ├── LLM 流式调用
                │       ├── publish(LLM_CHUNK) × N
                │       │       ├── CLI: print_thinking_chunk / print_response_chunk
                │       │       └── Server: ws.send_json({type: "thinking_delta"/"content_delta"})
                │       │
                │       └── publish(AFTER_LLM_CALL)
                │               ├── CLI: 收尾流式状态、统计 token
                │               └── Server: ws.send_json({type: "usage"})
                │
                ├── 需要工具调用？
                │       ├── publish(BEFORE_TOOL_CALL)
                │       ├── ToolExecutor.execute()
                │       └── publish(AFTER_TOOL_CALL)
                │               ├── CLI: render_tool_call()
                │               └── Server: ws.send_json({type: "tool_call"})
                │
                ├── publish(ON_FINISH)
                │       └── CLI: 设置完成标志
                │
                └── 返回 AgentState
```

### 3.2 多消费者并行处理

EventBus 的 `asyncio.TaskGroup` 确保所有 handler 并发执行：

```python
async with asyncio.TaskGroup() as tg:
    for handler in handlers:
        tg.create_task(self._invoke_handler(handler, event))
```

这意味着：
- CLI 的终端渲染
- Server 的 WebSocket 推送
- 日志记录
- 自定义插件的事件处理

**全部并行执行，互不阻塞**。

## 4. 关键设计决策

### 决策 1：为什么 handler 异常不向上传播？

因为事件系统是**观测设施**而非**决策设施**：
- 日志记录失败 → 不应中断 Agent 执行
- 前端推送失败 → 不应中断 Agent 执行
- 异常隔离确保核心逻辑的稳定性

### 决策 2：为什么 Plugin 的 install/activate/deactivate 都是 async？

因为插件安装/激活过程可能涉及 I/O：
- MCP 插件需要连接外部进程/服务
- 未来插件可能需要网络请求
- async 接口为插件提供完整的异步能力

### 决策 3：为什么当前只有 MCPPlugin 一个内置插件？

这是**最小可用产品（MVP）**原则的体现：
- 插件系统的抽象接口先定义好
- 一个真实插件（MCPPlugin）验证接口的合理性
- 未来可按需添加：日志插件、监控插件、自定义工作流插件等

## 5. 扩展指南

### 开发自定义插件

```python
from nexus.plugins.base import Plugin
from nexus.core.event.event_types import EventType

class MyPlugin(Plugin):
    name = "my_plugin"
    version = "1.0.0"
    
    async def install(self, agent):
        # 注册自定义工具
        agent.tool_registry.register(MyCustomTool())
        
        # 订阅事件
        await agent.events.subscribe(
            EventType.AFTER_TOOL_CALL,
            self._on_tool_call
        )
    
    async def activate(self):
        # 启动后台任务
        self._task = asyncio.create_task(self._background_worker())
    
    async def deactivate(self):
        # 取消后台任务
        if self._task:
            self._task.cancel()
    
    async def _on_tool_call(self, event):
        # 自定义事件处理
        print(f"Tool called: {event.payload['tool_name']}")
```

### 注册插件

```python
from nexus.core.factory import create_agent

agent = create_agent(config)
await agent.install(MyPlugin())
```
