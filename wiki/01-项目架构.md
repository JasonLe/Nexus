## 2. 核心设计决策

### 2.1 为什么 Runtime 和 Policy 要分离？

**传统框架的问题：**

```python
# 传统硬编码循环
while True:
    response = llm.chat(messages, tools)
    if response.has_tool_calls:
        result = execute_tools(response.tool_calls)
        messages.append(result)
    else:
        return response.content
```

- 一个循环打天下，不同模式塞进 `if-else`
- 修改模式必须改核心调度代码
- 测试必须跑完整循环

**Nexus 的分离方案：**

```python
# Runtime：只负责"如何执行"
while True:
    action = await policy.next_action(context)
    if isinstance(action, LLMCallAction):
        await execute_llm(action)
    elif isinstance(action, ToolCallAction):
        await execute_tool(action)
    elif isinstance(action, FinishAction):
        break

# Policy：只负责"下一步做什么"
class ReActPolicy(ExecutionPolicy):
    async def next_action(self, context):
        # 纯决策，无副作用
        if has_tool_calls(context.state):
            return ToolCallAction(...)
        return LLMCallAction(...)
```

### 2.2 为什么用类而非函数定义工具？

1. **内部状态管理** —— 工具可以有连接池、缓存、限流器
2. **继承与多态** —— 可定义工具族基类
3. **统一元数据获取** —— `isinstance(obj, BaseTool)` 即可安全获取 name/description/schema
4. **可测试性** —— 可 mock 工具实例

### 2.3 为什么 State 修改集中在 Runtime？

数据流方向：**Runtime → State → Policy**（单向）

- Runtime 修改 State（写入执行进度、工具结果）
- Policy 只读 State（基于当前状态做决策）
- 所有状态变更集中在 Runtime，便于审计和回滚

## 3. 模块依赖关系

### 3.1 核心层内部依赖

```
agent.py
  ├── runtime.py
  │     ├── context.py  ← 聚合 state + llm + tool_executor + events
  │     ├── state/types.py
  │     ├── event/event_bus.py
  │     ├── event/event_types.py
  │     ├── executor/actions.py
  │     ├── executor/policy.py
  │     ├── llm/base.py
  │     ├── tools/registry.py
  │     └── tools/executor.py
  ├── llm/base.py
  └── tools/base.py
```

### 3.2 应用层依赖核心层

```
cli/main.py
  ├── core/factory.py       ← Agent 组装工厂
  ├── core/agent.py
  ├── cli/config.py
  ├── cli/repl.py
  └── cli/session.py

server/app.py
  ├── core/factory.py
  ├── core/agent.py
  ├── cli/config.py
  └── cli/session.py
```

**关键设计：** `core/factory.py` 是 Agent 组装的**单一入口**，CLI / Server / REPL 三个调用方都只调这一个入口，避免代码重复。

## 4. 数据流

### 4.1 一次 Agent 运行的完整数据流

```
用户输入 task
    │
    ▼
Agent.run(task) ──→ 构建 initial_messages（system prompt + 历史）
    │
    ▼
Runtime.run() ──→ 创建 AgentState ──→ 创建 ExecutionContext
    │
    ▼
派发 BEFORE_AGENT_RUN 事件
    │
    ▼
while True:
    │
    ├──→ Policy.next_action(context) → Action
    │
    ├──→ 派发 BEFORE_(LLM|TOOL)_CALL
    │
    ├──→ 执行 Action
    │       ├── LLMCallAction → llm.chat/stream_chat → 更新 state.messages
    │       └── ToolCallAction → tool_executor.execute → 更新 state.messages
    │
    ├──→ 派发 AFTER_(LLM|TOOL)_CALL
    │
    └──→ 检查 FinishAction / ErrorAction → 跳出循环
    │
    ▼
派发 ON_FINISH / AFTER_AGENT_RUN
    │
    ▼
返回 AgentState
```

### 4.2 WebSocket 流式数据流（Server → Frontend）

```
前端发送 message
    │
    ▼
WebSocket /ws/chat ──→ _ChatConnection.handle()
    │
    ▼
agent.run(content, initial_messages=history)
    │
    ▼
Runtime 执行过程中通过 EventBus 派发事件
    │
    ├──→ LLM_CHUNK → on_llm_chunk → ws.send_json({type: "thinking_delta"/"content_delta"})
    ├──→ AFTER_LLM_CALL → on_after_llm → ws.send_json({type: "usage"})
    ├──→ AFTER_TOOL_CALL → on_after_tool → ws.send_json({type: "tool_call"})
    └──→ ON_ERROR → on_error → ws.send_json({type: "error"})
    │
    ▼
run 完成 → ws.send_json({type: "done", session_id, steps, usage})
    │
    ▼
前端 chatStore 接收 WS 消息 → 更新 React 状态 → UI 重渲染
```

## 5. 扩展点

### 5.1 添加新 LLM Provider

继承 `BaseLLM`，实现 `chat()` 和 `stream_chat()`：

```python
from nexus.llm.base import BaseLLM, LLMResponse, LLMChunk, ToolCall, UsageStats

class GeminiLLM(BaseLLM):
    async def chat(self, messages, tools=None, **kwargs) -> LLMResponse:
        ...
    async def stream_chat(self, messages, tools=None, **kwargs) -> AsyncIterator[LLMChunk]:
        ...
```

然后在 `nexus/core/factory.py` 的 `create_llm()` 中注册即可。

### 5.2 添加新工具

**方式一：@tool 装饰器（推荐）**

```python
from nexus.tools.decorators import tool
from nexus.tools.base import BaseTool, ToolResult

@tool(name="weather", description="查询天气", schema={...})
class WeatherTool(BaseTool):
    async def execute(self, args):
        return ToolResult.ok(data={"temp": 25})
```

**方式二：手动继承 BaseTool**

```python
class TimeTool(BaseTool):
    @property
    def name(self): return "get_time"
    @property
    def description(self): return "获取当前时间"
    @property
    def schema(self): return {...}
    async def execute(self, args):
        return ToolResult.ok(data={"iso": "2024-01-01T00:00:00Z"})
```

### 5.3 添加新 Policy

```python
from nexus.core.executor.policy import ExecutionPolicy
from nexus.core.executor.actions import LLMCallAction, FinishAction

class MyPolicy(ExecutionPolicy):
    async def next_action(self, context):
        # 只读 context.state，返回 Action
        return FinishAction(message="Done")
```

### 5.4 添加新 Plugin

```python
from nexus.plugins.base import Plugin

class MyPlugin(Plugin):
    @property
    def name(self): return "my-plugin"
    async def install(self, agent):
        agent.events.subscribe(EventType.BEFORE_LLM_CALL, self._on_before)
    async def activate(self): pass
    async def deactivate(self): pass
```

## 6. 配置体系

五级配置优先级（从高到低）：

1. **命令行参数**：`--model gpt-4o --api-key sk-xxx`
2. **环境变量**：`NEXUS_MODEL`、`NEXUS_API_KEY`、`NEXUS_PROVIDER` 等
3. **项目级配置**：`<work_dir>/nexus.yaml`（向上查找到 `.git` 边界）
4. **用户级配置**：`~/.nexus/nexus.yaml`
5. **内置默认值**：openai/anthropic/minimax 默认参数

配置文件支持 `${ENV_VAR}` 和 `${ENV_VAR:-default}` 环境变量引用语法。
