# 10 - 项目运行与开发指南

> 教学视角：理解架构是「知其然」，能运行和修改是「知其所以然」。本章从代码出发，讲解如何从零开始搭建环境、运行各模块、以及遵循项目的工程规范进行开发。

---

## 1. 环境准备

### 1.1 依赖安装

```bash
# 克隆仓库
git clone <repo-url>
cd Nexus

# 创建虚拟环境
python -m venv venv
source venv/bin/activate  # macOS/Linux
# venv\Scripts\activate  # Windows

# 安装核心依赖
pip install -e "."

# 安装 CLI 依赖（含 prompt_toolkit、rich 等）
pip install -e ".[cli]"

# 安装 Server 依赖（含 fastapi、uvicorn 等）
pip install -e ".[server]"

# 安装全部依赖（开发推荐）
pip install -e ".[dev]"
```

### 1.2 前端环境（Desktop）

```bash
cd desktop
npm install
```

## 2. 快速启动

### 2.1 CLI 模式

```bash
# 方式 1：REPL 交互模式
nexus

# 方式 2：单次执行
nexus "写一个快速排序算法"

# 方式 3：带参数执行
nexus "分析这个文件" --provider anthropic --model claude-sonnet-4-20250514

# 方式 4：恢复最近会话
nexus --continue
```

### 2.2 Server 模式

```bash
# 启动 HTTP + WebSocket 服务
nexus serve --port 8321 --host 127.0.0.1

# 启动服务并自动打开浏览器
nexus ui
```

### 2.3 Desktop 模式

```bash
# 1. 先启动后端服务
cd <项目根目录>
nexus serve

# 2. 在另一个终端启动前端开发服务器
cd desktop
npm run dev

# 3. 启动 Electron（开发模式）
npm run electron:dev
```

### 2.4 生成配置文件模板

```bash
nexus --init-config
# 在当前目录生成 nexus.yaml 模板，填入 API Key 后即可使用
```

## 3. 配置文件示例

### 3.1 最小可用配置

```yaml
# ~/.nexus/nexus.yaml（用户级配置）
providers:
  openai:
    api_key: sk-your-key-here
    model: gpt-4o-mini

default_provider: openai
```

### 3.2 多 Provider 配置

```yaml
providers:
  openai:
    api_key: sk-xxx
    model: gpt-4o
    max_tokens: 4096
    context_window_tokens: 128000
  anthropic:
    api_key: sk-ant-xxx
    model: claude-sonnet-4-20250514
    max_tokens: 4096
    context_window_tokens: 200000
  minimax:
    api_key: sk-minimax-xxx
    model: MiniMax-Text-01
    base_url: https://api.minimaxi.com/anthropic

default_provider: openai
stream: true

agent:
  system_prompt: "你是一个编程助手，擅长 Python 和前端开发。"
  max_steps: 30

tools:
  enabled:
    - read_file
    - write_file
    - list_dir
    - search_content
    - shell
```

### 3.3 环境变量引用（安全推荐）

```yaml
providers:
  openai:
    api_key: ${OPENAI_API_KEY}           # 从环境变量读取
    model: ${OPENAI_MODEL:-gpt-4o-mini}  # 带默认值
```

## 6. 开发规范

### 6.1 代码风格

- **格式化**：Black（行宽 100）
- **类型注解**：全部使用 Python 3.10+ 类型语法（`str | None` 而非 `Optional[str]`）
- **导入排序**：标准库 → 第三方 → 内部模块
- **文档字符串**：Google Style

### 6.2 关键约束（来自 project_memory）

| 约束 | 说明 |
|------|------|
| `raise X(msg) from e` | 异常链必须使用 `raise ... from`，`return X(msg) from e` 是语法错误 |
| `messages.stream()` | Anthropic SDK 的 stream 方法不接受 `stream=True` 参数 |
| `auto_truncate=False` | 会话持久化默认保留全量历史 |
| 工具目录 | 工具必须放在 `/nexus/tools/` 目录 |
| LogRecord | `message` 属性是保留字，自定义日志数据用 `warning_text` 等替代键 |
| `session_id` | 新会话必须生成唯一 `session_id`，防止覆盖已有会话 |
| Agent 工厂 | Agent 组装逻辑必须集中在 `nexus/core/factory.py` |
| `restore` 消息 | 恢复历史会话时，`restore` 消息必须携带原始 `session_id` |
| 项目级 `nexus.yaml` | 不应包含 `tools` 字段，避免覆盖用户级配置 |
| WebSocket | 连接必须动态引用 `app.state.agent` 以应用配置变更 |
| `/api/tools` | 必须返回所有 5 个内置工具，不论当前 Agent 注册状态 |
| `['__none__']` | Agent 工厂必须处理此哨兵值以禁用所有工具 |

### 6.3 错误分类

LLM 错误必须分类为：
- **可重试错误**（`LLMRetryableError`）：网络超时、速率限制、服务端错误
- **不可重试错误**：认证失败、参数错误、内容过滤

## 8. 扩展开发指南

### 8.1 添加新的 LLM Provider

1. **创建 Provider 类**：
```python
# nexus/llm/providers/my_provider.py
from nexus.llm.base import BaseLLM

class MyProviderLLM(BaseLLM):
    async def chat(self, messages, tools=None, **kwargs) -> LLMResponse:
        # 实现非流式调用
        pass
    
    async def stream_chat(self, messages, tools=None, **kwargs) -> AsyncIterator[LLMChunk]:
        # 实现流式调用
        pass
```

2. **注册到工厂**：
```python
# nexus/core/factory.py::create_llm()
elif provider == "my_provider":
    from nexus.llm.providers.my_provider import MyProviderLLM
    return MyProviderLLM(...)
```

3. **添加默认配置**：
```python
# nexus/cli/config.py::_default_providers()
"my_provider": ProviderConfig(
    model="my-model",
    max_tokens=4096,
),
```

### 8.2 添加新的内置工具

1. **创建 Tool 类**：
```python
# nexus/tools/my_tool.py
from nexus.tools.base import BaseTool, ToolResult

class MyTool(BaseTool):
    @property
    def name(self) -> str:
        return "my_tool"
    
    @property
    def description(self) -> str:
        return "工具功能描述（LLM 会阅读此描述决定何时调用）"
    
    @property
    def schema(self) -> dict:
        return {
            "type": "object",
            "properties": {
                "param1": {"type": "string", "description": "参数说明"}
            },
            "required": ["param1"]
        }
    
    async def execute(self, args: dict) -> ToolResult:
        # 执行逻辑
        return ToolResult.ok(data="结果", tool_name=self.name)
```

2. **注册到工厂**：
```python
# nexus/core/factory.py::register_tools()
from nexus.tools.my_tool import MyTool
all_tools = {
    # ... 现有工具
    "my_tool": MyTool(),
}
```

### 8.3 添加新的 Event 类型

1. 在 `nexus/core/event/event_types.py` 的 `EventType` 枚举中添加新类型
2. 在 Runtime/Policy 的适当时机调用 `await events.publish(Event(type=NEW_TYPE, payload={...}))`
3. 在 CLI/Server 中订阅新事件类型并处理

## 10. 故障排查

### 10.1 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `nexus` 命令找不到 | 未安装或不在 PATH | `pip install -e ".[cli]"` |
| API Key 无效 | 配置错误或环境变量未设置 | 检查 `~/.nexus/nexus.yaml` 或 `NEXUS_API_KEY` |
| 工具调用失败 | 工作目录不匹配 | 检查 `--work-dir` 参数 |
| MCP 工具不显示 | MCP server 未连接 | 检查 `/mcp list` 状态，尝试 `/mcp reconnect` |
| 配置修改不生效 | Agent 未重建 | Server 端 PUT /api/config 会自动重建；CLI 需重启 |
| 会话未保存 | 未正常退出 | CLI 用 `/save` 手动保存；Server 每次 run 后自动保存 |

### 10.2 日志分析

日志文件位于 `~/.nexus/logs/`，按会话 ID 命名。关键日志标记：

```
[DEBUG] nexus.core.factory: Tool registered: read_file
[INFO] nexus.cli.repl: Task executed, steps=3, tools=1, tokens=1024
[WARNING] nexus.server.app: MCP 初始化失败，跳过 MCP 能力
[ERROR] nexus.cli.repl: Task execution failed
```
